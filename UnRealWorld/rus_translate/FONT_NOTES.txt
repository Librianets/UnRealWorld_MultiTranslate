Шрифт нового вывода, проверка 2026-10-15

Источник: UnReal_World_RPG/work/translate/3.88/exe/URW.FNT.
Копия: translate/URW.FNT, 20480 байт.
SHA256: 31262772a5f5076fb2b1554a0843dfee6fc244d782d72d29e64a9acbd96c5fac.

Формат: 256 глифов, 8x10 байт на глиф; byte=1 означает пиксель.
Кодировка русских глифов CP1251, не CP866 и не UTF-8. Проверены реальные
пиксели: слот C0 — А, DF — Я, E0 — а, E6 — ж, F0 — р. В CP866 эти байты
обозначали бы другие символы. Старый patch_rus.py кодирует перевод CP1251.
Исходный английский текст не надо пропускать через CP1251 ради поиска
совпадения: ASCII совпадает, расширенные байты требуют исходной кодировки.
Новый UTF-8 каталог преобразовать Unicode -> CP1251 только для отображения.
Если символ не представим, диагностировать и оставить исходный английский.

В чистой 3.88:
- sub_514840 загружает шрифт;
- 00514F0C: mov esi, ds:fopen;
- 00514F15: push "rb";
- 00514F1A: push "URW.FNT";
- 00514F1F: call esi; адрес возврата 00514F21;
- 00514F3B: fread(&unk_A5B9278, 0x5000, 1, stream), затем fclose.
IAT fopen = preferred VA 00589478, импорт
api-ms-win-crt-stdio-l1-1-0.dll. Фактическую функцию CRT брать из разрешённого
слота IAT текущего процесса, с поправкой на ASLR. ABI __cdecl:
FILE* fopen(const char* filename, const char* mode).

Для подмены пути проверить одновременно адрес возврата 00514F21, точное
имя URW.FNT и режим rb. Передать реальному CRT fopen путь translate/URW.FNT;
возвращаемый FILE* далее читает/закрывает оригинальный CRT. Прочие fopen,
игровые ресурсы и game/URW.FNT оставлять без изменения. Этот файл описывает
требование; сам Python-генератор не устанавливает перехват.

sub_50B9D0 преобразует байты C4->8E, E4->84, F6->94. В выбранном FNT эти
пары глифов попарно побайтно одинаковы, что проверено. Дополнительное
преобразование для них не требуется. sub_50B1E0 рисует глифы по одному байту.

Ограничение leaf: sub_50B9D0 и нижний sub_50B1E0 копируют текст без
проверки длины в буферы по 300 байт. Новый перевод не должен превышать
299 байт CP1251. При превышении оставить исходный текст и записать причину.
Это ограничение безопасности нового обработчика, а не разрешение увеличивать
уже переполненный исходный буфер.
